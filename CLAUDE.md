# HalfGripEureka (Eureka Mine)

A Half Grip (Steam app 4163270, Unity 6, Windows) mod that adds one race map: **Eureka Mine**, a caricature of a Pennsylvania coal
mine (no one mine: breakers, culm banks and patch towns from the anthracite fields, drifts and tipples from the bituminous ones).
The race starts in the pithead yard, runs down a slope into the mine, and every lap after that is underground. The release is
`EurekaMine/mod.json` (`version`, `gameVersion`, `tools`): 0.2.0 for game 0.419 and HalfGripTools 1.0.6 at the time of writing.

## How the mod runs

- A **source mod** for [HalfGripTools](https://github.com/4l3x4nd3r0/HalfGripTools): at game start the loader compiles
  `EurekaMine/src/*.cs` (C# 10, netstandard2.1) against the game's DLLs, BepInEx, 0Harmony and HalfGripTools. What ships is the
  `EurekaMine/` folder (`mod.json`, `icon.png`, `src/`, `sprites/`).
- Like Highway and Temple of Drift (4l3x4nd3r's [HalfGripMods](https://github.com/4l3x4nd3r0/HalfGripMods), MIT) it has no scene: it
  copies the `StadiumAsh` map entry into `RunConfig.maps` with its own track index (40), patches `MenuManager.TrackIndex` to load the
  Stadium, and on `sceneLoaded` hides the Stadium's ground, track and decoration and builds the map in code.
- Conventions from ProcTrack (`htubdawg/ProcTrack`): the bots' paths rebuilt with waypoints every 20 units and 2 samples per gap,
  added grid slots for seven rivals, materials without `HideAndDontSave`, `Mod.Info` for the verbose log, try/catch round the build
  with `Unload()` putting the Stadium back.

## Layout of the repo

| Path | Role |
|---|---|
| `art/route.py` | Curve maths: anchor poses joined by Dubins (curve-straight-curve) paths of a set radius, or a helix; sampling every 8 units; height smoothing |
| `art/layout.py` | **The layout** (anchors of the lap, the two alternate routes and the run in), the checks (grades, 34 units of vertical clearance wherever roads overlap in plan), the drawings, and the bake into `EurekaMine/src/RouteData.cs` |
| `art/make_icons.py` | `icon.png` and `sprites/eureka_icon.png` (12x12, like the game's map icons) |
| `art/preview/` | Pictures of the built mine without the game (see Checking changes) |
| `docs/plan.png` | The plan drawing the README shows (copy of `art/layout.py`'s output) |

`EurekaMine/src/`:

| File | Role |
|---|---|
| `Mod.cs` | Config, scene hook |
| `MapEntry.cs` | The map entry (track index 40, time objectives scaled by lap plus a third of the run in, an overcast copy of the Stadium's ash weather without ash) |
| `Patches.cs` | `MenuManager.TrackIndex`, TestMode (`RunState.BeginRace`, `RunMap.Generate`) |
| `RouteData.cs` | Generated by `art/layout.py`. Never edit by hand |
| `Route.cs` | The roads (`Road`): points, widths, forks and joins; `InsideOther` (is a point inside another road's corridor) |
| `MeshKit.cs`, `Textures.cs` | `Batch` (one mesh per texture/tint/behaviour), `Mats` (materials from the scene's ground shader), textures painted in code |
| `Mine.cs` | The tunnels swept along each road (floor, rock-dusted walls with the coal band, chamfer, bolted roof; width and roof per point), side passages (`Niche`), timber sets, rails, lamps, rubble, the drift portal, the start line |
| `Props.cs` | What fills the niches (machinery, curtains, stoppings, supplies...), utilities on the walls, chevrons on the bends, the signs, the pit bottom's shaft station and loading tracks |
| `Pithead.cs` | The surface: ground, hill with highwalls, breaker, culm banks, siding, houses, church, headframe, boiler house |
| `SceneBuilder.cs` | Orchestrates the build; the lap line and the four bot paths; the grid; labels |
| `RunIn.cs` | Lap 1's run in: the lap-counter prefix, the player reset on the slope, the bots' slope path and handover, the gate |
| `Underground.cs` | Darkness and headlights underground (Temple of Drift's method), and the lamp light pool |
| `Hazards.cs` | Runaway mine cars on the plane, coal chutes, ventilation doors on the chute |

## The lap

Levels (layout heights; the game's are 80 lower, so the yard is at y 0, where the game spawns rivals at y 1): haulage 0, lower
gangway about -42, the dip -66, the upper seam up to -24, upper gangway +40, the yard +80. Marks (main lap points) are in
`RouteData.MarkNames`/`MarkIndex`.

- **Alternate routes** are separate roads that leave and rejoin the main lap. Where a branch still overlaps the lap's floor it takes
  the lap's height (`settle` in `layout.py`), so the floors are one floor until the roads part; walls, sets and lamps inside another
  road's corridor are left out (`Route.InsideOther`), and a branch floor tile is dropped only when all four corners lie on the lap's
  floor.
- **Lap counting** across stacked levels uses the game's own `TrackManager.allowFigureEightTracks` (each car tracked from its last
  sample). The lap line is the main lap only; bots get four paths (main, seam, chute, both) and `LapManager.GetRandomPath` deals one.
- **The run in** is not part of the closed lap line. `RunIn.Project` (prefix on `LapManager.GetCarProjectedPoint`) keeps a car on
  lap -1 with `totalDistance` behind the line until it reaches the bottom, then seeds `carLastClosestIndex` at the merge.

## Rules that matter

- **Change the layout in `art/layout.py`, never `RouteData.cs`.** Run it and read its checks: `clearance problems ... 0`, grades.
- **Bump `version` in `mod.json` with every change that ships**, and the version line in `README.md`. Set `gameVersion` and `tools`
  to the current game and HalfGripTools at the same time.
- C# 10 and netstandard2.1 only. Tabs, `///` summaries that say why.
- No people on the map (the owner's call): hazards are machinery.
- No vanilla hazards (the owner's call): the Stadium's `HazardsSpawner_FINAL` is hidden.
- **Lights:** the renderer gives each object only a few lights, so every batch is cut into 120-unit cells (`Batch.ToMeshes`) and
  the lamp pool's lights are `Auto`, never `ForcePixel` (0.1.0 had one mesh per batch across the whole mine and Important lamp
  lights: the headlights lit nothing). Keep both.
- Don't invent an `ObjectiveKind`. Never change `MapEntry.MapName` (saves find the map by it).

## Checking changes

The private repo `htubdawg/HalfGripRefs` has the game's DLLs, scene dumps and tools:

- **Layout:** `python3 art/layout.py [outdir]` (needs matplotlib, numpy): lap length, grades, crossings, clearance, drawings, and it
  rewrites `RouteData.cs`.
- **Compile:** `HalfGripRefs/tools/check-mod.sh EurekaMine/src` must print `0 Error(s)` and `0 Warning(s)`.
- **Members named by string** (Harmony targets, `Traverse`, `AccessTools`): check them against a decompile of `Assembly-CSharp.dll`
  (ilspycmd, see HalfGripRefs' `tools/README.md`): `LapManager.GetCarProjectedPoint`/`carLastClosestIndex`, `MenuManager.TrackIndex`,
  `TrackManager.SpawnEnemies`/`playerStart`/`startPositions`, `EnemyController.lastSearchIndex`, `PlayerResetLogic.player`,
  `PathManager.samplesPerSegment`/`snapLanesToGround`/`snapRayHeight`/`InitializePath`.
- **Pictures without the game:** `art/preview/run.sh <outdir>` compiles `Mine`, `Pithead`, `Route`, `MeshKit` and `Textures` against a
  stand-in for UnityEngine and draws the meshes with three.js in headless Chromium. Plain colours, no game lighting: for shapes and
  junctions. Add a shot to `art/preview/shots.py` for whatever changed.
- **In game** only the owner can test. Say what to look at and which log lines (`Debug.VerboseLog`) tell the outcomes apart.
